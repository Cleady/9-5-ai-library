Cho thuật toán tìm kiếm nhị phân (Binary Search) sau đây thực hiện trên một dãy đã sắp xếp gồm \(n\) phần tử: \(a_1 < a_2 < \dots < a_n\). 

procedure binary_search(x: integer, a1, a2, ..., an: integers)
    i := 1
    j := n
    while i < j
        m := floor((i + j) / 2)
        if x > a[m] then i := m + 1
        else j := m
    if x = a[i] then location := i
    else location := 0
return location

Hỏi trong trường hợp xấu nhất (worst-case), số phép so sánh (các phép so sánh giữa phần tử \(x\) và \(a_m\), cộng thêm phép so sánh kiểm tra điều kiện lặp) cần thực hiện khi kích thước mảng \(n = 32\) là bao nhiêu?

A
Tối đa \(5\) phép so sánh vì \(\log_2(32) = 5\).
B
Tối đa \(6\) phép so sánh khóa, vì thuật toán lặp qua \(\lfloor\log_2(32)\rfloor + 1 = 6\) lần lặp kiểm tra.
C
Tối đa \(32\) phép so sánh như tìm kiếm tuần tự.
D
Tối đa \(16\) phép so sánh.

Bước 1: Phân tích số lần chia đôi của thuật toán

Tại mỗi bước của vòng lặp while i < j, khoảng tìm kiếm từ \(i\) đến \(j\) bị thu hẹp đi một nửa: \[\text{Kích thước còn lại} \approx \left\lceil \frac{j - i + 1}{2} \right\rceil\]

Bước 2: Tính toán cho trường hợp \(n = 32\)

Bắt đầu với đoạn độ dài 32. Sau mỗi lần chia đôi: \[32 \longrightarrow 16 \longrightarrow 8 \longrightarrow 4 \longrightarrow 2 \longrightarrow 1\] Tổng số lần lặp vòng lặp để đưa đoạn về độ dài 1 là \(\log_2(32) = 5\) lần.

Bước 3: Đếm phép so sánh cuối cùng

Sau khi thoát khỏi vòng lặp tại \(i = j\), thuật toán thực hiện thêm đúng 1 phép so sánh điều kiện: \[x = a[i]\] Do đó, tổng số phép so sánh đối với phần tử mảng trong trường hợp xấu nhất là \(5 + 1 = 6\) phép so sánh.
